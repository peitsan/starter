# MRD — 市场需求文档（摘要）

> 完整版见仓库 [`docs/MRD.md`](https://github.com/peitsan/starter/blob/master/docs/MRD.md)。

## 目标用户

Windows 用户中，被"开机越来越慢 / 启动项一团乱"困扰的人：

- 装了很多软件、开机要等很久的普通用户
- 有多块硬盘、开机时 IO 冲突导致卡死的进阶用户
- 想让 AI 直接帮忙管理启动项的开发者 / 极客

## 痛点与解决方案

| 痛点 | 占比 | Starter 方案 |
| --- | --- | --- |
| 开机慢、启动项混乱 | 高 | 可视化统一管理 + 延迟/排序 |
| 多盘 IO 冲突卡死 | 中 | F6 IO 感知节流 ⭐ |
| 手动操作繁琐 | 中 | F11 CLI / F12 MCP 自动化 |

## 竞争分析

| 竞品 | 局限 | Starter 差异 |
| --- | --- | --- |
| 任务管理器 → 启动 | 只启停，无调度 | F3–F6 完整调度 |
| 各种国产加速器 | 常捆绑 / 无 IO 感知 | 开源 / IO 感知 |
| DelayedStartupToolPro | 无 IO 感知 / 无 Agent 接口 | F6 + F12 MCP |

## 关键指标（KPI）

- 启动时间优化幅度
- IO 冲突导致的卡死次数下降
- Agent（MCP）接入成功率 / 审计覆盖率 100%
