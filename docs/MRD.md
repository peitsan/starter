## 1. 一句话定位

一个 **Windows 启动项管理软件**，重点解决 **多盘 IO 冲突** 与 **冷启动/热启动慢** 的问题，提供比 Windows 自带「任务管理器 → 启动」更精细的 **启动队列调度、IO 优先级控制、延迟启动分组**。

## 2. 背景与现状

### 2.1 用户的痛点（自述）

- 本机硬盘数据量大，**多盘 IO 冲突** 导致卡死。
- Windows 自带的「启动」面板只能 **开关**，不能：
  - 设定 **延迟启动**（几秒/几分钟后才允许启动）。
  - 设定 **启动顺序**（哪些先就绪、哪些必须等依赖启动后再起）。
  - 设定 **IO/CPU 优先级**（防止抢盘、抢 CPU）。
  - 设定 **启动互斥/串行**（同组内只允许 N 个同时启动，避免瞬时风暴）。
  - 设定 **磁盘占用冷却**（磁盘 IO 高于阈值时暂停下一批启动）。

### 2.2 现有方案盘点

| 方案 | 优点 | 不足 |
|---|---|---|
| **Windows 任务管理器 → 启动** | 系统级、零成本 | 只能开关，不能调度 |
| **Windows「启动」文件夹** | 简单 | 加载时机不可控 |
| **DelayedStartupToolPro**（参考） | 支持延迟、依赖、并发数 | UI 较老、Win11 风格差、无 IO 感知 |
| **Autoruns (Sysinternals)** | 全面、专家级 | 面向高级用户，学习成本高，无调度 |
| **BootRacer / Soluto** | 启动耗时可视化 | 商业、不开源、对 IO 调度无能为力 |
| **dsh-launcher**（参考） | 现代化 UI（推测） | 不针对启动项调度，仅是个 launcher |

### 2.3 市场空白

- 国内/中文用户对 **延迟启动、启动顺序、IO 节流** 有需求，但**几乎没有面向普通用户的现代化方案**。
- 现有工具要么过于极客（Autoruns），要么 UI 古早（DelayedStartupToolPro）。

## 3. 目标用户

| 用户画像 | 描述 | 优先级 |
|---|---|---|
| **A. 重度本地玩家 / 内容创作者** | 多盘（大容量 SSD/HDD 混合）、常驻后台服务多、装各种优化软件 | P0 |
| **B. 极客 / 折腾型用户** | 喜欢精细控制启动行为、能接受复杂配置 | P0 |

> 本项目 MVP 主要服务 A + B，C 群用户也能用得上但不是首要目标。

## 4. 核心价值主张

1. **可视化启动时间线**：用甘特图 / 泳道图展示「谁在 0s 起、谁在 30s 起、谁依赖谁」。
2. **IO 感知调度**：实时监测磁盘 IO 负载，在 IO 高时**自动暂停**下一批启动项，避免雪崩。
3. **延迟 + 顺序 + 依赖**：延迟启动只是基础，要做就做 **DAG 依赖图 + 启动队列**。
4. **现代化 UI**：参考 dsh-launcher 的风格，目标 **Win11 Fluent / Mica 材质**。
5. **跨平台雏形**：技术栈 **React Native**（Windows via react-native-windows 或 react-native-desktop），便于将来扩展 macOS/Linux。

## 7. 范围 & 非范围

### 7.1 In Scope（MVP）

- 扫描所有 **Windows 启动项**（注册表 Run/RunOnce、启动文件夹、计划任务「登录时」、服务「自动」）。
- 启/停单个启动项。
- 设定 **延迟时间**（0s / 5s / 30s / 1m / 自定义）。
- 设定 **启动顺序**（拖拽排序）。
- 设定 **简单依赖**（A 启动完再起 B）。
- 设定 **并发上限**（同时最多 N 个启动）。
- **IO 感知节流**（读取磁盘队列长度 / 占用率，超阈值暂停下一批）。
- 启动时间线可视化（甘特图）。
- 配置文件导入/导出（JSON）。

### 7.2 Out of Scope（暂不做）

- 服务/驱动深度管理（Autoruns 那套，先不碰）。
- 计划任务的复杂条件（按时间/事件触发，先只支持「登录时」）。
- 沙箱/虚拟化启动（避免搞成 Sandboxie 那种）。
- 云端同步、账号系统。
- 自动检测「推荐禁用项」AI 建议（可作为 v2 探索）。

## 8. 风险与依赖

| 风险 | 等级 | 缓解 |
|---|---|---|
| **react-native-windows 在 Win11 上稳定性** | 高 | 备选 Electron / Tauri，UI 层与 RN 解耦 |
| **修改启动项需管理员权限** | 中 | 申请 UAC 提权时明确提示 |
| **IO 监控 API 选型**（ETW vs. WMI vs. PerformanceCounter） | 中 | MVP 用 PerformanceCounter 简单实现，v2 切 ETW |
| **误关系统关键服务** | 高 | 标注「关键项」，默认禁改；操作前二次确认 |
| **影响系统安全软件（杀软）信任度** | 中 | 代码签名；不上传任何用户数据 |

## 9. 技术栈预览

- **前端**：React Native (react-native-windows) + TypeScript（如未来上 macOS 再谈 react-native-macos）。
- **状态管理**：Zustand（轻量、跨平台友好）。
- **UI 库**：Fluent UI React（贴合 Win11 风格）。
- **原生侧**：
  - **C# / C++** 桥接层（读写注册表、WMI 启动项枚举、ETW 事件、IO 监控）。
  - 通过 **TurboModules / JSI** 暴露给 JS。
- **数据**：本地 SQLite（启动项配置、调度历史）。
- **打包**：MSIX（Win11 现代安装包）。
